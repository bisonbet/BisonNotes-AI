## Slice-A caller and failure matrix

| Caller/context | Persistence-dependent work | Unavailable behavior and enforcement |
| --- | --- | --- |
| `PersistenceController` | Open the durable SQLite store and expose the view context | `ready`, `explicitlyEphemeral`, and `unavailable` are distinct. `requireDurableStore()` accepts only `ready`; no fallback or replacement is attempted. |
| `AppDataCoordinator` and `CoreDataManager` | Pending-mutation queue migration, Summary/CloudKit configuration, initialization, and iCloud observers | Queue migration and dependent configuration/initialization are withheld; coordinator remains uninitialized and cloud reconciliation/observation returns. |
| `BisonNotesAIApp` and `ContentView` | Startup migrations, cleanup, cache maintenance, Share/Inbox scans, background tasks, Watch setup, and main-content construction | The app shows an accessible storage-unavailable view and instructs a close/reopen retry. Lifecycle work returns before consuming or deleting owned inputs; background handlers register even when storage is unavailable and complete unsuccessfully. External file-open requests show resubmission guidance rather than claiming retention. |
| `BackgroundProcessingManager` and `TranscriptionStarter` | Load/resume persisted jobs and process queued work | Manager construction returns before job loading when the production store is unavailable; `TranscriptionStarter` no longer eagerly constructs it. |
| Audio/transcript import and data migration managers | Copy files, create Core Data rows, and save/import migrated data | Entry points return before filesystem or Core Data work; source inputs remain available for a later relaunch. |
| Recorder workflow, interruptions, and Watch ingestion | Attach the workflow, save finalized recordings, write Watch audio, and send recovery work | Workflow/Watch setup and persistence-dependent notification paths are withheld; Watch payloads remain with the sender and no permanent audio/row/ack is created. |
| Native macOS persistence-backed scenes | Construct views that fetch or mutate the library | Settings, review, recording, transcript, summary, list, and processing windows render the unavailable view instead of persistence-backed content. |

The failure surface contains only a sanitized domain/code chain for diagnostics; raw `NSError.userInfo`, file paths, credentials, and content are not retained or logged by the readiness layer. Existing SQLite, `-wal`/`-shm`, audio, sidecar, Share/Inbox, and Watch inputs are not removed, reset, rebuilt, or replaced.

## Test seams and schema decision

The schema-preserving A/B decision is to keep the current model, store URL, file-protection option, and Core Data migration options unchanged. The only migration-related behavior added is a readiness guard around the existing queue/data-migration callers; import migration infrastructure and the model remain outside slice A.

Debug tests can inject a sanitized `PersistenceStoreFailure` without touching the normal library. The slice-A tests exercise explicit ephemeral storage, one-store durable SQLite readiness, invalid URLs with no fallback, deterministic sanitized failure, fixture reopenability after a failed attempt, and coordinator/import/migration startup withholding. Assertions inspect `persistentStores` so a failed single-store load cannot look like a successful empty library.
