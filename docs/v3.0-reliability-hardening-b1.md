- `testProcessingJobReadFailurePreventsStartupAndExecution()` asserts a failed job load records `jobLoadError`, leaves no runnable jobs, and prevents a later job start.

## Review fixes

The follow-up review remains within B1 and preserves the schema and existing slice-A changes:

- `stageTranscriptDeletion` reads recordings and summaries before clearing either relationship. A summary-read failure leaves both the original links and unrelated pending context edits intact; no broad rollback is needed.
- `deleteSupersededDuplicates` groups recording IDs instead of constructing a dictionary that traps on duplicates. It retains candidate content when either its ID-based or direct relationship points to an ambiguous recording identity.
- `fetchRecording(url:) throws` uses the existing decoded stored-path/container-fallback rules and does not rewrite rows during lookup. Relationship refresh and file-deletion preparation use this throwing boundary. The existing optional `getRecording(url:)` remains a compatibility wrapper for legacy callers outside this B1 conversion; it is not a durability/error-propagation guarantee, and those mutation callers remain part of later caller audits.
- Relationship refresh stages the replacement cache before publishing/saving it. A late transcript/summary read failure leaves the existing cache intact. The helper decomposition removes the three new serious lint violations without changing the baseline or suppressing rules.
- Four new tests cover failure on the summary fetch after a successful recording fetch, duplicate recording IDs during pruning, encoded/moved recording URLs plus lookup failure, and relationship-cache preservation after a late fetch failure. The read-failure seam can now select an operation so tests do not always fail the first fetch.
