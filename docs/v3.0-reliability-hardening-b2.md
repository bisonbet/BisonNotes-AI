## Scope and ownership

This report records B2 only: durable recording, transcript, summary, and
processing-job save acknowledgement, plus the caller changes required to keep
failed saves and failed identity reads from authorizing dependent work. The
uncommitted slice-A and B1 implementation, review fixes, Phase 0 report, and
user-provided plan were preserved. No files were staged, committed, pushed, or
reset. Work stops before C.

The Core Data model and model version are unchanged. Existing store-loading and
import/migration infrastructure was not replaced. Fault injection uses the
DEBUG-only Core Data seam and disposable in-memory or temporary disk-backed
stores; it does not target the normal library or a live CloudKit account.

## API and caller changes

| Boundary | Implementation and callers | Failure contract |
| --- | --- | --- |
| Recording creation | `RecordingWorkflowManager.createRecording`, `AppDataCoordinator.addRecording`, and `addWatchRecording` now throw. Recorder finalization, interruption/recovery/segment flows, Mac finalization, Watch delivery, imports, Combine, UI-test fixtures, and background recording creation use the throwing result. | The UUID is returned only after the row is durably saved. Backup scheduling, success publication, dependent processing, and Watch acknowledgement happen after that acknowledgement. The workflow mutation uses a sibling context; both successful and failed saves leave unrelated pending view-context edits staged. |
| Transcript creation/replacement | `RecordingWorkflowManager.createTranscript` and coordinator wrappers throw while preserving the legitimate `UUID?` no-output case. Background transcript persistence, live fallback, rerun/editor flows, transcript import, interruption/recovery, and UI-test callers propagate failure. | The sibling context rolls back failed transcript/recording mutations. A failed transcript save cannot complete the job, publish completion, or release the source. Prior output and verified recoverable output remain available for retry. |
| Summary creation/upsert | `RecordingWorkflowManager.createSummary`, coordinator wrappers, background summarization, summary regeneration, import/restore, and summary views use throwing persistence. AI name updates now pass through the throwing coordinator/Core Data path before the rename notification. | The primary new summary is committed before old-summary cleanup or name publication. Failed save leaves prior summaries and owned recovery state intact; no summary-completed success or dependent cleanup is emitted. |
| Processing jobs | `CoreDataManager.createProcessingJob`, `updateProcessingJob`, `deleteProcessingJob`, and `deleteCompletedProcessingJobs` throw. `BackgroundProcessingManager` now persists before appending/replacing active state, requires a successfully loaded job store, and persists completion before notifications or source cleanup. | Failed create blocks execution and leaves no false active job. Failed update/delete leaves the last committed job state. Failed completion leaves the job non-completed and its artifacts/source available for reconciliation or retry. |
| Identity and collection reads used by mutation | Mutation callers use throwing `fetchRecording(id:)`, `fetchRecording(url:)`, transcript/summary lookups, and complete snapshots. The legacy optional URL wrapper remains only for display/refresh and excluded legacy-migration compatibility; it is not used to authorize cleanup or job work. | A failed read is distinct from absence. Cleanup, cloud reconciliation, import deletion, source deletion, job execution, and empty-library success paths stop or retain prior state rather than treating `nil`/`[]` as proof of absence. |
| File/Watch/background boundaries | `EnhancedFileManager`, `RecordingArchiveService`, import managers, recorder finalization/recovery, Watch integration, and background cleanup were updated around durable-save boundaries. Summary-preserving deletion reads the required summary before deleting a transcript. | Source and sidecars are retained until the required metadata/job save succeeds. Watch sends no success acknowledgement on a failed local save. Post-commit filesystem cleanup is retryable and cannot undo a committed metadata decision. |

UI loaders retain the previously loaded snapshot when a read fails and show a
load/save error; they do not replace valid data with an empty fallback or
fabricate a successful empty-library state.

## Failure-path tests and invariant mapping

`BisonNotes AITests/Swift6PersistenceIsolationTests.swift` contains the
DEBUG-only B2 fault-injection coverage:

- `testB2WorkflowSaveFailuresThrowAndDoNotLeakFailedRows` covers recording,
  transcript, and summary save failures and verifies unrelated pending fields
  survive a later save.
- `testB2ProcessingJobSaveFailuresDoNotAuthorizeExecutionOrCleanup` covers job
  create/update/delete and completed-job cleanup failures, including a failed
  collection read during job creation.
- `testB2SuccessfulMutationsSurviveClosingAndReopeningStore` verifies durable
  recording, transcript, summary, and queued-job state after closing and
  reopening a disk-backed store.
- `testSummaryReadFailureStopsPreservingDeleteBeforeTranscriptRemoval` proves a
  failed required summary read leaves the transcript, recording row, and source
  file untouched before the preserve-summary deletion path can mutate anything.

The pre-existing B1 read-failure tests remain in the same focused class and
continue to cover cleanup, cloud selection, job startup, relationship-cache
retention, and optional URL-resolution behavior.

## Review fixes and current validation

The B2 review found and fixed three correctness gaps: app-level Share/Inbox/open
handlers consumed sources after import managers had swallowed a save failure;
Watch failure handling left the transfer in flight indefinitely; and workflow
saves committed unrelated pending view-context edits on success.

- Import managers now return the exact successfully persisted source URLs. Open,
  Inbox, and Share cleanup only consume acknowledged sources. Failed and
  unsupported inputs remain, and Share authorization is rearmed when inputs remain.
- Watch metadata-save failure reports `success: false`, allowing the receiver to
  end its background task, clear in-flight deduplication, and accept a retry.
  It does not mark the recording processed or send a success acknowledgement.
- Recording, transcript creation/replacement, and summary workflow writes use
  the existing sibling-context mutation helper, preserving pending UI edits on
  success as well as failure.
- Persistence controllers share one loaded managed-object-model instance,
  avoiding repeated generated-class entity registrations across test stores.
  The former 134020 failures did not reproduce in two subsequent no-retry runs;
  this is observed regression evidence, not proof against all Core Data failures.
- Small helper/type extractions removed all seven newly introduced serious lint
  violations. The unused transcript lookup helper was removed after call-site
  verification. No lint suppression or committed baseline change was added.

New tests cover a real audio import save failure followed by retry, mixed-batch
cleanup, Watch retry using the same UUID with no live WCSession, and disk-backed
workflow success preserving an unsaved rename and unrelated insertion.
